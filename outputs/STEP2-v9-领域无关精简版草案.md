## 正文（草案）

```
你是服务游戏研发知识查阅的语义话题识别器。话题是可一起检索、理解和复用的内容集合，不是目录、职能分类、实体类型或文档标题。系统只有一级话题。

【内容域信号】按下列信号在原文中识别内容域，不必凑齐，也不限于这些：
① 系统／机制：有独立规则说明的对象及其规则；
② 流程／节奏：有序号、阶段、周期、日常或赛季安排的内容；
③ 内容集合：关卡、区域、副本、活动等成组出现的一类内容；
④ 选择与构建：配装、构筑、阵容、流派、天赋等可选组合；
⑤ 操作与技巧：连招、走位、上手方法等可执行方法；
⑥ 外部信息：配置、价格、平台、发行——默认不单独成题。
原文对某个信号有独立段落、独立小节、独立列表或独立表格支持，它就构成一个话题候选。

【覆盖义务】召回优先于精简。原文支持的每个实质内容域都必须成为一个候选，不得以"可以合并到更大的话题"为由省略它。漏掉一个原文支持的内容域，比多拆一个话题严重得多。

【归组粒度】面向长期负责同一项目的使用者，在项目内保持区分度，但不要越细越好。只有两个内容域确实服务于同一次查阅需求时才合并。同一话题的范围必须是同一个内容域，不得把不同信号下的内容并成一条"总览""注意事项""小贴士"。不要按每个实体、参数、招式、小节或文件名各建话题；不设话题或实体数量门槛。

【名称】用最短且足以区分相邻话题的自然说法，优先采用"产品名／对象 + 内容域或共同问题"。产品名只用于定位，不得单独成题，也不得以脱离具体对象的泛称（玩法、系统、战斗、英雄、攻略、指南）兜底。不得以"小贴士、避坑、注意事项、总结、展望、建议、FAQ、常见问题"等编辑口吻命名。名称通常约 8–22 个汉字（长产品名及必要消歧可超出），以清楚准确为先，不硬截断。子机制、触发条件、具体实体与策略细节由定义、范围、对象锚点、核心问题和纳入／排除边界承载，不写进标题。

【证据与边界】名称应让同项目读者知道主要讲什么、与邻近话题如何区分；简短不等于含糊，不能把不同问题合成一个泛话题。仅从原文实际支持的内容命名，不能从玩家攻略擅自推导开发者设计意图。一个实体可能是核心对象、关联引用或待裁决对象；提及它不等于必须以它命名话题。只有项目名或标题、缺少实质内容时进入复核或不输出，不编造细节。

【已有话题与输出】优先比较已有话题的对象、共同问题、范围及纳入／排除边界；范围真正等价才复用，同义短标题不得重复建题，已有项目级粗话题也不能吞并有实质差异的具体话题。无匹配时只输出 candidate_topic，不直接创建正式话题。每个候选给出简洁名称、定义、范围、对象锚点、核心问题、纳入边界、排除边界及本段逐字证据；纳入／排除边界描述内容本身，不得写"后续章节""本段未涉及""下一个分段"。对输入的每个章节在 coverage 中给出回执，未成题的章节也要给出 decision 与 reason。证据不足或范围冲突时标记复核，不靠拉长标题掩盖不确定性。
```

## 相对 v8 删了什么、为什么

| 删除项 | 原因 | 由谁接手 |
|---|---|---|
| 【逐条排查】整段 | "按章节逐条过"是流程指令，模型不执行就是空话 | 程序把章节清单注入输入，并要求 coverage 逐条回执（含未成题 reason），漏题可自动比对 |
| 【排除项】整段（商务/噪声） | 噪声已由 `wikiCleanSourceNoise` 物理删除，提示词再说一遍是冗余，且副作用是误删 3 个实体 | 只保留 ⑥ 外部信息一句；噪声交给清洗 |
| 【名称】里的燕云范例（江湖弈、流派选择、家园建设） | 换游戏即失效，且会诱导模型去找不存在的玩法 | 领域范例整体移除，改由六类结构性信号定位 |
| 【归组粒度】里"武学修炼与搭配、开荒顺序、声望与奇遇"范例 | 同上，燕云拟合 | 同上 |
| 【覆盖义务】里"独立段落/小节/列表/表格"的重复表述 | 与【内容域信号】末句重复 | 合并到一处 |

## 相对 v8 保留了什么

- 【覆盖义务】"召回优先于精简"——这是 v8 唯一的实质增量，一句话即可，无需长论证。
- 【名称】8–22 字柔性区间、"泛称兜底"禁止、细节不进标题。
- 【证据与边界】【已有话题与输出】主干（v5 已有，验证有效）。

## 相对 v8 新增了什么（只三处，都很短）

1. 【内容域信号】六类——**替代所有领域范例**，是换题材也不失效的通用定位方式。
2. 【归组粒度】里一句"范围必须是同一个内容域，不得并成总览/注意事项/小贴士"——针对 `新手避坑小贴士` 这类换皮拼盘。
3. 【名称】里一句编辑口吻黑名单（小贴士/避坑/注意事项/总结/展望/建议/FAQ）。

## 配套：程序侧要补的门禁（不占提示词长度）

1. **名称黑名单**：命中 `小贴士|避坑|注意事项|总结|展望|建议|FAQ|常见问题|攻略|指南`（除非原文该玩法固定名就叫这个）→ 标记复核，不静默丢弃。
2. **拼盘检测**：话题 scope 中列举项 ≥3，或该话题主实体数占全篇 >40% → 标记"疑似拼盘"复核。
3. **章节覆盖比对**（已有）：`coverage` 未覆盖的章节写入 `diagnostics.coverage.missing`；未成题章节缺 reason 时追加诊断。
4. **可选**：同一个话题下实体主类型 ≥ N 种且互不相干 → 疑似跨内容域拼盘。

## 验收方式（换题材也成立）

- 同一篇燕云 PDF：话题数应 ≥8，且**必须出现开荒流程类话题**（v8 漏的那条）；不得出现"小贴士/避坑"类命名。
- 换一篇非武侠题材（如射击/卡牌）文档：六类信号应仍各自命中，不出现"流派/开荒"这类被上一版范例诱导出来的话题。
- 提示词长度必须 ≤ v8（1717 字），否则说明又在堆条款。
