## 一、可直接复制（v2 全文）

```
你是在话题语境中工作的 Entity 候选抽取器。候选必须同时满足：可明确指代、有实质证据、有具体复用价值。
【逐条排查】把每个已确认话题的名称、范围与纳入边界当作检索清单，逐条在该话题语境内找出承担它的具名对象：人物、NPC、地点、区域、关卡、副本、道具、任务、事件、技能、机制。先枚举具名对象，再判断系统与概念。禁止只用「XX系统」「XX玩法」这类集合名词覆盖整段而漏掉其中的具名对象。
孤立参数、纯标题、泛称和整段文档不得建实体。只出现一次不等于孤立参数：孤立参数指脱离具体对象的裸数值与裸规格行；有名字、有归属的对象即使只提及一次也应建候选。
分类不确定但有价值时进入 review。抽候选时同步给出本体类型、现实或虚构语境、产品/IP、版本四个身份锚点的初步判断并各附逐字证据；锚点不足时置 review，不得因锚点未定而丢弃候选。集合描述型候选（「XX系统」「XX玩法」这类概括名称）同样要给主类型：按其主要职能选最具体的一个 active 类型，其余职能写进 candidate_tags；不得用「系统」「机制」「对象」等宽泛类型兜底；只有词表确实无类型可命中时才填 null 复核。
每个候选必须输出规范名称、简明定义、别名和可回跳的逐字证据。证据须为原文连续片段并直接包含该实体名或其明确指代，不得用段落摘要、改写或跨句拼接替代。
候选按价值准入，不设固定条数。相同身份的多处提及汇集证据，保留版本和身份属性；忽略侧栏、登录提示、推荐文章等与正文无关的网页杂项。
```

## 二、v1 → v2 改了什么

只在第 4 段末尾追加一句（+128 字），其余五段**一字未动**：

> **新增**：集合描述型候选（「XX系统」「XX玩法」这类概括名称）同样要给主类型：按其主要职能选最具体的一个 active 类型，其余职能写进 candidate_tags；不得用「系统」「机制」「对象」等宽泛类型兜底；只有词表确实无类型可命中时才填 null 复核。

### 为什么要加

v1 首轮实测（`两版对比-2026-10-16T08-20-18-974Z.xlsx`）实体 27 → 42、关系 11 → 22、隔离关系 1 → 0，整体明确为正；唯一新增的小瑕疵是**主类型待复核 0 → 2**，两个对象都是集合描述型实体：

| 实体 | 模型给的本体类型 | 主类型 |
|---|---|---|
| 探索系统 | 玩法系统（集合描述） | **待复核：原候选未选择主类型** |
| 声望与奇遇系统 | 玩法系统（集合描述） | **待复核：原候选未选择主类型** |

有意思的是，同一轮里其他系统级实体**都**正常拿到了主类型（`武学系统/内功系统/奇术系统` → `ET-SYS-SKILL`，`家园系统` → `ET-SYS-HOUSING`，`多人系统` → `ET-SYS-SOCIAL`）。所以不是"系统级一律选不出类型"，而是**概括性、复合性的名称**（"探索"、"声望与奇遇"）让模型不敢选。

副作用是整合决策从 `ready` 变成 `type_review`——仍可预览/写入，但状态降了一级。

### 这句怎么起作用的

1. **按主要职能选最具体的一个 active 类型** —— 逼模型做取舍而不是留空；
2. **其余职能写进 candidate_tags** —— 给"声望与奇遇"这种复合名称一个合规出口，不用硬塞进单一主类型；
3. **不得用「系统」「机制」「对象」等宽泛类型兜底** —— 这句是保护性的，不能省。

## 三、为什么必须带那句"不得用宽泛类型兜底"（重要）

`index.html` 的 `finalizeModelResult` 里有一道**硬门控**：

```js
if(['对象','机制','系统','美术','音频','技术','产品','其他'].includes(tags.entity_type))
  hard.push('BROAD_ENTITY_TYPE_FORBIDDEN');
```

也就是说，如果为了"不许留空"把模型逼急了，让它吐出一个 `系统` 当主类型，后果不是多一条复核，而是 **hard_failures → 整个分段不可预览**。

所以这句是配重：**既要它选，又要它不许瞎选。** 两者缺一，要么多 2 条复核，要么直接翻车。

## 四、预期与验证

**预期**：主类型待复核 2 → 0，整合决策回到 `ready`，实体数与关系数基本持平（42 / 22 附近）。

**风险**：

- 若模型把"探索系统"硬套成 `ET-SYS-*`（如成长/技能系统）而实际不贴切，会变成**错误主类型**而不是待复核——这比留空更糟。跑完要看这两个实体最终落到哪个 `主类型ID`；
- 若新增后主类型待复核没降反升，或出现 `BROAD_ENTITY_TYPE_FORBIDDEN`，立即回退到 v1（512 字那版）；
- 字数 +128，对耗时的影响可忽略（v1 的耗时成本主要来自实体数本身）。

**验证**：仍按老规矩，同一份 PDF 连跑，看实体数、关系数、主类型待复核、隔离关系、耗时五项。重点看**主类型待复核是否归零且没有换来硬门控失败**。
