# 游戏研发知识 Wiki · MVP

把游戏研发文档（PDF / DOCX / Markdown / TXT）解析成 **语义话题 → Entity → Tag / Relation** 的可检索知识库。

一句话分工：**模型只做语义判断和结构化建议；程序负责解析、主数据、稳定 ID、证据与词表校验、权限、幂等写库与发布门控。**

## 仓库内容

| 路径 | 说明 |
| --- | --- |
| `wiki-demo-mvp/` | 应用本体。纯静态 SPA：`index.html` + `pipeline.js` / `semantic-tags.js` / `file-manager.js` / `prompt-history.js`，无构建步骤 |
| `.playwright-cli/` | 回归测试。Playwright + mock 浏览器，用 `vm.Script` 与 `page.route` 喂本地 `pipeline.js`，**不调用真实模型** |
| `outputs/*.md` | 开发规格、产品方案、各版提示词与实测评估 |
| `.workbuddy/memory/` | 项目决策日志（按天） |

## 主线流程

```
来源解析 → 一级语义话题 → Entity → Tag 与 Relation → 多维筛选与证据消费
```

1. **来源解析**：提取正文 → 清站点噪声 → 按标题/章节切段（段间重叠 160 字）。
2. **话题阶段**：模型只出话题候选 + `coverage` 章节覆盖回执。
3. **实体阶段**：按已确认话题抽 Entity，**不得新增话题**；只下发精简输入。
4. **全文整合**：模型只输出归并映射，不重写证据、不新增实体。
5. **组装校验**：程序重定位证据、复核外键、隔离异常项。

## 关键不变式

- **证据逐字可复核**：`source.slice(start, end) === exact_quote`（`end` 为开区间，UTF-16 偏移）。
- **候选全部有去向**：无法确认的归并保持独立并标 `review`，不合格项隔离进诊断，不静默丢弃、不静默发布。
- **不自动修补被截断的 JSON**；`finish_reason='length'`、拒答、空流一律不算成功。
- **超时即抛错**：150 秒无数据 / 300 秒总时限，不做静默截断。
- **受控词表**：主类型与关系都只能选云端已保存的 active 项，未命中只生成 `candidate_*` 待治理。
- **模型不得直接创建正式话题、Tag 或写库。**

## 提示词治理

- 版本历史不可变：每版保存基线/新版 STEP2–5 与全局整合全文，服务端时间戳 + 变更步骤 + 备注；可恢复，不可删改旧历史。
- **不得靠不断加长提示词修问题**：能由程序保证的事一律不写进提示词。
- 提示词保持**领域无关**，禁止写入题材特有的范例。
