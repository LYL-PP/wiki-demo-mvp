# 2026-09-23

- 根据现有《知识Wiki & 知识图谱》方案和产品截图，修正知识首次入库 PRD 的顶层模型：Wiki 根目录固定为 Entity 与 Spec 两类；Entity 按产品、对象、机制、系统、美术、音频、技术、其他/未归类抽取词条，Spec 按团队手册、游戏设计、美术设计、程序技术、音频设计、项目管理、质量测试、Demo、管线分类并按语义聚合主题。明确同一源文档可同时产出两类内容，图谱是 Entity 关系视图而非第三类知识，并补充 Entity/Spec 双向关联、增量更新、冲突处理和分轨评价指标。
- 按进一步需求将分类机制重构为 Entity/Spec 各自独立的三级分类：一级为专业域，二级为项目/产品语义域，三级分别为 Entity 对象类型与 Spec 规范主题类型；将场景与世界设为独立域，Demo/纪要等改为内容形态标签，并补齐跨域/跨项目、类目准入、置信度门控和完整路径评价指标。交付《知识首次入库与Wiki Entity-Spec三级分类规则PRD.html》。
- 基于 Schema.org、Wikidata、W3C SKOS、OASIS DITA、SharePoint 托管元数据、Atlassian Teamwork Graph 与 IGDA 等公开实践，将方案升级为“浅层本体 + 多维分面 + 动态视图”：Entity 采用自然对象类型及有证据的语义关系，Spec 采用主题域 × 信息类型，项目/专业/版本等改为正交分面；补充词表治理、动态界面、评价体系与落地计划，交付《游戏研发知识Wiki Entity-Spec分类与本体规则PRD.html》。
- 按最终产品范围将方案收敛为 Entity 单轨，彻底移除 Spec：前台采用“知识空间 → 语义话题 → 实体条目”，标签仅描述实体类型与适用范围，不承担目录职责；AI 通过话题路由、标签过滤、关系扩展和证据回跳联合检索。补充话题/标签边界、入库门控、相似钻取、原型、功能需求及与纯标签方案的对照指标，交付《游戏研发知识Wiki Entity语义分类与标签规则PRD.html》。
