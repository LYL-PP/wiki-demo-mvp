## 实体配图（新增独立旁路阶段）
- 需求：解析完所有实体 → 写入知识浏览之前，再解析来源图片并匹配到实体词条；**必须相对独立，不能影响已有流程**。
- 用户选择：PDF + DOCX；IndexedDB 存原图 + 96px 缩略图；规则 + 模型辅助；一图带候选清单（一次请求带 ≤5 候选）；**全部图片都过模型复核**。
- 模型辅助的含义是**模型读图片内容**做是否匹配的判断，再由程序做综合判定（不是读文字候选）。
- 实现：新文件 `wiki-demo-mvp/entity-images.js`，只在 `runCurrent` 一处接入（`addLocalPreview` 之前），整体 try/catch，失败降级为无配图。
- 判定矩阵：强规则(≥4 分)+模型确认→rule+model；弱规则(1–3)+模型 high/medium→model；模型否决→不采纳；模型不可用→强规则降级 rule，弱规则不采纳。模型返回清单外 entity_id 丢弃并诊断。
- 关键实现坑：
  1. pdf.js 3.11 图片对象常是 `{bitmap,width,height}`（无 `kind`/`data`），必须优先取 `bitmap`。
  2. mammoth `convertToHtml` 对自造/部分 DOCX 会崩，且拿不到稳定位置；改用 JSZip 解包 `word/media/*` + `document.xml` 的 `a:blip` 顺序。
  3. IndexedDB 事务封装里 `fn(store)` 返回 Promise 时要 `Promise.resolve(result)` 再取 `.result`，否则只读游标返回的是 `{result:[...]}` 对象。
  4. 既有测试的 route 未给 `/entity-images.js` 兜底会返回 HTML → 页面 "Unexpected token '<'"；已批量补上路由（8+4 个测试文件）。
